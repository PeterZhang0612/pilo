# Remote WebUI 多地址配置与一次扫码配对

## 目标

同一 Pilo 主机支持局域网、外网域名、组网等多个访问地址。手机浏览器只扫描一次二维码，先进入认证选择页，再手动点击各地址，在目标 origin 完成认证；后续在对应网络打开不带凭证的普通书签即可使用。

示例（端口以实际配置为准）：

- 家里：`http://192.168.2.1:<port>`
- 外网：`https://pi.hsingjui.de`
- 组网：`http://10.0.0.2:<port>`

## 已确认的用户决策

- 不要求统一 origin，不引入新的代理、DNS 或认证基础设施。
- 一次扫码后通过认证页面手动点击目标地址，不直接进入聊天，不自动批量认证，不批量打开弹窗。
- 配对 secret 自签发起 10 分钟有效，device token 自兑换成功起 30 天有效；两者独立计时。
- 桌面端重启后，已有有效设备 token 保留，未完成的旧配对链接作废，需要新扫码授权；不恢复旧配对会话。
- 桌面端只有一个通往认证页面的二维码，入口固定为默认局域网地址；认证页面列出所有配置地址。入口切换 UI 已在后续简化中移除。
- 地址名称仅作为历史字段保留，桌面不再提供名称编辑或展示，只展示实际地址。
- 用户要求先创建任务并规划；最终规划随后已获批准，任务已进入实现。

## 规划时的现有行为与约束

- 外部地址是单个 public_base_url，只决定访问链接与二维码基址，不限制 token 的访问地址。证据：`src-tauri/src/runtime/remote/manager.rs:183`、`:216`、`:331`。
- 当前配对 secret 有效期 5 分钟、单次使用，兑换成功会立即重新生成。证据：`src-tauri/src/runtime/remote/auth.rs:9`、`src-tauri/src/runtime/storage/remote.rs:73`、`src-tauri/src/runtime/remote/api/middleware.rs:60`。
- 当前 device token 有效期 30 天。证据：`src-tauri/src/runtime/remote/auth.rs:10`。
- 当前配对链接使用 ?pair=，WebUI 从 query 读取；成功后保存 origin-local localStorage token 并清除 URL。证据：`src-tauri/src/runtime/remote/manager.rs:220`、`src/remote/remote-app.tsx:41`、`src/remote/use-remote-connection.ts:114`、`:115`。
- 无 token 页面仅显示需要配对的提示。证据：`src/remote/remote-app.tsx:284`。
- 服务启动会生成新 secret。证据：`src-tauri/src/runtime/remote/manager.rs:280`。
- 浏览器各 origin 存储互不共享，不可达的地址无法预先认证；认证页面本身也必须由手机当前可达的地址提供。
- 独立 token 提供独立记录和吊销，不等于严格 origin 权限隔离。可复用 secret 泄露可能消耗剩余名额。
- fragment 只避免配对凭证随普通页面 URL 请求发送，不能替代 HTTPS；HTTP 配对和认证流量仍有链路窃听风险。

## 需求

### R1 认证选择页与跳转

- 桌面端支持配置多个完整访问地址。
- 扫码首先进入认证选择页，列出所有有效配置地址的手动跳转入口；仅打开选择页不消耗兑换名额，不自动进入聊天。
- 点击目标地址后，该 origin 独立兑换和保存 device token；成功后可进入聊天，也能返回原认证页继续配对其他地址，不要求再次扫码。
- 某地址不可达时，不将其标为已认证，其他已完成地址继续可用；在配对授权尚有效时可再次点击尝试，授权失效则明确提示需要新配对链接。
- 不向没有有效配对授权的访客公开活跃 secret；普通未认证页面仅提示如何获取配对授权。
- 桌面配置与手机认证交互须支持窄屏、键盘与触控，并兼顾 safe-area。

### R2 凭证与配额生命周期

- 一次配对会话使用一个可复用 secret，地址集合以生成会话时的配置为准；配置几个有效、不同 origin 的地址，就有几个地址兑换名额。
- 每地址一个名额；重复点击、请求重试和并发兑换不额外消耗其他地址名额，不重复生成设备记录。
- secret 10 分钟有效，名额用满或桌面端重新生成时，不再签发新授权；上述失效不撤销已签发的有效 token。
- device token 30 天绝对有效，可单独吊销，不自动续期。
- 授权签发失败不丢失可重试的名额；响应丢失可安全重试，不得仅凭公共的可复用 secret 取回别人已签发的 token。
- 未完成配对的浏览器临时上下文只需支持同标签页刷新、跳转及返回，不承诺关闭标签页后的恢复；到期或发现失效后清理凭证。
- 不持久化服务端明文 secret / token；桌面重启作废旧配对会话，已有设备授权不受影响。
- 修改地址集合或实际 URL 时，旧配对授权不能继续向变更后的目标发放凭证；不因此清空已有设备授权。

### R3 配置与链接展示

- 地址名称仅作为历史字段保留；桌面与配对页只展示实际地址，不编辑名称。
- 桌面只显示一个认证页二维码，入口固定为默认局域网地址（存在 `lan` 时）；不再提供入口切换，因此也没有「切换入口不消耗名额」的说法。
- 新配对 URL 仅用 #pair= 携带短期 secret，不用 query，也不把 device token 放进 URL。
- 读取配对参数后尽早清除地址栏中的凭证。
- 桌面提供重新生成配对链接入口，不增加 TTL 配置项。
- 合法的旧单地址配置可升级为新配置，已有有效设备授权保留；不悄悄丢弃不合法的旧地址，应提示用户修正。

## 验收标准

- [ ] AC1 / R1：配置示例中的三个地址，一次扫码先进入认证选择页，不自动进入聊天、不消耗兑换名额；手动点击三个地址入口后，各 origin 均可进入 WebUI，无需重复扫码。
- [ ] AC2 / R1、R3：三个地址完成配对后，同一浏览器在 token 有效期内打开无凭证的普通书签均无需重新配对。
- [ ] AC3 / R1、R2：不可达地址不被标为已认证；在授权有效期内恢复可继续配对，其他已认证地址正常使用；超时后明确提示获取新配对链接。
- [ ] AC4 / R2：正常配对三个地址产生三条独立设备记录，可分别吊销；不宣称 token 严格绑定某个 origin。
- [ ] AC5 / R2：重复点击、同一请求重试或并发请求不额外扣其他地址名额；设备写入失败不丢失名额，响应丢失可安全重试。
- [ ] AC6 / R2：名额用满、到期或重新生成后，旧 secret 无法签发新 token；已有有效 token 不受影响，已签发 token 不因重试延长有效期。
- [ ] AC7 / R3：新配对链接只在 fragment 中携带短期凭证，推荐书签和配对完成后的地址栏不含 secret 或 device token。
- [ ] AC8 / R1、R3：普通未授权访客拿不到活跃 secret；桌面端和手机 WebUI 均能操作相关入口。
- [ ] AC9 / R3：合法单地址配置可升级，已有设备授权不因迁移无故删除；非法旧配置得到明确修正提示。
- [ ] AC10 / R2：桌面端重启后，旧配对链接不能签发新 token，已有有效设备 token 仍可访问，未完成地址需要新的扫码配对授权。
- [ ] AC11 / R3：桌面显示一个二维码且入口固定为默认局域网地址；手机页显示各地址按钮，仅展示实际地址。
- [ ] AC12 / R2：没有原请求重试证明的调用者，不能仅凭共享 secret 与地址 ID 领取已签发 token；被吊销 token 不得由旧配对收据恢复。

## 不在范围内

- 统一 origin、增加 Caddy / DNS / SSO 等基础设施。
- 批量弹窗、自动顺序跳转、跨 origin 后台静默认证。
- device token 放进 URL 或书签。
- 不可达地址立即认证、无限期免扫码、token 自动续期。
- 严格 origin 权限绑定、不同地址权限分级、永久保存配对会话。
- 重做现有端口变更策略、主题、Service Worker 或聊天运行时。
- 未经用户另行明确要求修改或创建测试，或执行测试 / 构建。
