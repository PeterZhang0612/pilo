# 下一句话预测与内置扩展固定部署

## 目标

为 Pilo 提供类似 Claude Code 的下一句话预测，减少用户输入重复后续指令的成本；同时将 Pilo 内置扩展统一为随 pilo-server 部署的固定单文件，为后续扩展功能复用已有 Pi 能力。

## 背景与现状

- Pi JSONL 是会话事实来源，预测是辅助输入能力，不能成为新会话消息或修改主模型。
- Pilo 的正常聊天、WebUI 和模型探测已存在 Pi RPC 链路；内置扩展目前通过内联源码生成临时文件。出处：`crates/pilo-server/src/runtime_streams/pi.rs:181`、`:249`、`:389`。
- WSL/SSH 的 Server 已部署在 `~/.cache/pilo/server/`。出处：`src-tauri/src/runtime/server_deploy.rs:13`。
- `agent_settled` 已映射为会话最终结束事件，不能用中间工具轮次或低层 `agent_end` 触发预测。出处：`src-tauri/src/runtime/pi_events/mod.rs:48`、`:133`。
- 扩展 UI 转发已保留 Widget 字段，但桌面和 WebUI 的处理器尚未消费 `setWidget`。出处：`src-tauri/src/runtime/pi_event_adapters.rs:95`、`src/components/chat/use-pi-session-features.ts:260`、`src/remote/use-remote-extension-ui.ts:188`。
- 模型凭据和可用模型取决于 Pi 实际运行环境；SSH 工作区可以使用 Local Pi，配置作用域和执行环境不可混为一谈。出处：`src-tauri/src/runtime/pi_workspace.rs:55`。

## 已确认需求

### R1：预测内容

- 提示词以用户提供的 Claude Prompt Suggestion Generator v2 为基础，仅做 Pilo 和多语言必要适配，内嵌在扩展文件中。
- 预测用户自然会输入的下一句话，而不是助手认为应做的事；只给一个短句，匹配用户语言与风格，下一步不明确时允许无建议。
- 不使用 pi-next-cue 的“必须给建议，无法判断时输出 ok/continue”策略。

### R2：设置与共享配置

- 功能开关和预测模型按 Connection 保存，由桌面与 WebUI 共享，而不是各客户端 localStorage 独立保存。
- 默认关闭。开启后未指定模型时跟随当前聊天模型，用户也可单独指定预测模型。
- 关闭立即隐藏建议并取消或使未完成请求失效；重新开启不得因查看历史会话自动启动 Pi。
- 用户在设置中开启并选择预测目标即表示允许发送裁剪后的预测上下文；不增加跨模型、跨供应商的授权确认弹窗。
- 模型配置不修改聊天主模型，也不创建第二套 API Key 或供应商配置体系。

### R3：触发与采用

- 只针对当前可交互会话的完整结束触发，输入框非空、带附件、运行中、等待阻塞确认或只读会话时不显示。窗口失焦或进入后台仍可生成并保留预测，回到前台时显示，不因前后台切换新增请求。
- 空输入框显示一句 Ghost Text。桌面 Tab 接受，移动端提供可点按的采用入口；采用只填入草稿，仍需用户按现有方式发送。
- 开始输入、Esc、提交、切换会话或模型时隐藏并使旧结果失效。
- 保留现有命令/文件补全优先级、Tab 焦点导航、输入历史和中文输入法行为。
- 桌面与 WebUI 复用共享状态逻辑和 ChatComposer；覆盖窄屏、触控目标、安全区和软键盘布局。

### R4：上下文与隔离

- 使用 Pi 当前 Session 分支的有限用户/助手文本和必要压缩摘要；工具感知优先采用名称与成功/失败状态。
- 不额外发送完整工具输出、工具参数、thinking、图片或读取文件来补充预测上下文。
- 有明确上下文与输出预算，预测内容不写入 conversation 或 SQLite 会话缓存。
- 请求必须可取消且有超时；旧会话、旧草稿、旧模型或旧设置产生的结果不能重新显示或覆盖草稿。
- 预测失败、模型不可用、无建议不能阻塞或破坏聊天；不静默切换用户指定的预测模型。

### R5：内置扩展部署

- Pilo 内置扩展统一为 Server 源码目录内 `extensions/` 下的单文件；无第三方运行时依赖时不创建 package.json、独立 prompt 文件或 Package 子目录。
- 部署时与 Server 位于同一 Runtime 根目录的 `extensions/`；随 Server 一起部署更新，不用临时源码文件、bundle-hash 或独立扩展版本管理。
- 本任务包括新增预测扩展，以及现有 SSH workspace、模型目录探测内置扩展的迁移。现有出处：`src-tauri/src/runtime/pi_workspace.rs:55`、`src/lib/pi-model-catalog-extension.ts:21`、`src/lib/pi-models.ts:418`。
- 按用途显式加载，不因为统一目录而加载所有扩展：正常聊天加载预测，Local Pi/SSH 工作区按需加载 SSH 扩展，模型探测只加载探测所需扩展。
- 各 Session 专属动态配置不能通过改写共享扩展文件传递；升级不覆盖用户设置，不做运行中扩展热加载。
- Local、WSL、SSH 部署到实际运行 Pi 的环境；Local/SSH 工作区模式部署到 Local Runtime。
- 用户安装的第三方扩展继续由 Pi 原生机制管理，不搬进内置扩展目录。

## 不在范围内

- 多候选、半句话补全、自动发送、跨会话偏好学习。
- 第三方插件管理界面、通用插件市场、第二套安装体系、任意 React 组件扩展协议。
- 新建预测模型 SDK、凭据库、跨模型授权弹窗。
- 哈希版本目录、多版本共存、扩展独立回滚或热更新。
- 测试代码的新增或修改；用户未明确授权验证前不运行测试或构建。

## 验收标准

- [x] AC1（R1）：明确后续意图产生一句符合用户风格的建议；不明确、错误或敏感场景可保持无建议，不强制输出通用“继续”。
- [x] AC2（R2）：新 Connection 默认关闭；开启后默认跟随当前模型，指定模型后使用该模型，设置跨重启保留。
- [x] AC3（R2）：桌面修改设置后 WebUI 可读取同一状态，反向修改也同步；不同 Connection 不互相覆盖。
- [x] AC4（R2、R4）：启用并选择模型后直接按配置发送，不弹额外授权；关闭后不再发起预测，已有结果消失，迟到结果不显示。
- [x] AC5（R3）：每次完整结束最多一次实际预测调用；当前会话在窗口后台仍可生成，失焦或隐藏不取消请求、不丢弃结果，回到前台不重复生成；切换后的非当前会话、不符合输入状态的会话和重放的历史事件不新增预测请求，浏览 idle 会话不启动 Pi。
- [x] AC6（R3）：Tab 或触屏采用只填入，不自动发送；输入/Esc 隐藏；命令补全、焦点导航、输入历史和中文输入法不回归。
- [x] AC7（R4）：切换会话、fork、新一轮执行、草稿或模型/设置变化后旧结果不能出现；网络延迟、断线和多客户端订阅不导致串会话或重复实际调用。
- [x] AC8（R4）：无建议、超时、取消、凭据或模型不可用均不阻塞主聊天，不修改主模型，不新增预测 conversation 消息。
- [x] AC9（R5）：内置扩展固定部署、后续 Session 复用现有文件；开发/发布 Server 更新同步扩展，缺失文件可补齐，不保留任何内置扩展的临时源码路径。
- [x] AC10（R5）：Local、WSL、SSH 和 Local Pi/SSH 工作区各模式按需加载；模型探测不加载预测；两个 SSH Session 的动态配置相互隔离。
- [x] AC11（R3）：桌面与 WebUI 都可配置并使用；窄屏采用入口可触达，Ghost Text 不遮挡草稿、附件或软键盘区域。

## 风险与限制

- 预测会额外产生模型费用；取消不保证供应商完全停止计费，依靠默认关闭、单次调用、输入预算和超时控制。
- 指定预测目标会收到有限会话上下文。用户明确选择以设置授权，不增加确认流程；不能据此扩大上下文范围。
- 固定目录升级不提供运行中热加载或多版本保证，扩展新代码在重启 Pi 后生效；文件替换需保持完整性。
- 各环境 Pi 版本可能不同，实施时检查所用 API；不支持预测能力时保留正常聊天并提供轻量不可用状态，不实现推测性的旧事件回退。
