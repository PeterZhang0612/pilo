# 项目模型 Scope 与模型选择器搜索（issue #1）

## Goal

让用户在模型较多时快速搜索、选择模型，并在 Pilo 内方便地管理项目级 Scope；默认遵循 Pi 的 Scope，不修改任何 Pi 配置。

来源：https://github.com/hsingjui/pilo/issues/1，以及本次对话确认的项目覆盖与草稿编辑规则。

## Confirmed Decisions

- 项目未设置 Scope 时继承项目所在 Pi 运行环境解析后的默认 Scope，包括 Pi 自身的项目配置；Local、WSL、SSH 不混用默认值。
- 项目设置完全覆盖默认 Scope，不做合并，也不引入排除列表。
- 项目 Scope 是 Pilo 的项目偏好，跨会话保存；Pi 配置和独立运行的 Pi 不受影响。
- 编辑采用草稿：从当前生效列表初始化，可连续修改，最后一次性应用。
- 首次编辑继承列表不是从空列表开始；未修改或取消，不生成项目覆盖。
- 自定义空列表与未设置不同；清空不恢复继承。恢复继承必须是明确操作。
- 桌面应用与桌面布局的 WebUI 提供完整 Scope 编辑；移动窄屏仅使用 Scope，不提供编辑、批量操作或恢复继承。各入口复用共享组件，通过布局能力控制管理入口。

## Requirements

### R1. 搜索与模型视图

- 模型选择器提供“全部 / Scope”切换。
- 搜索覆盖模型名称、模型 ID 和供应商，支持不区分大小写的查询。
- 搜索和视图切换只改变显示结果，不修改当前模型或 Scope。
- 有合理的加载、失败、无可用模型、Scope 为空及搜索无结果状态；Scope 随全部模型使用同一轮目录加载与刷新，不在加载中误报未解析。
- 刷新模型后保持弹窗、当前视图、搜索和未提交草稿，不要求关闭重开才能看到刷新结果。
- 当前模型不在 Scope 中时仍显示当前模型，不因编辑 Scope 自动切换模型。

### R2. 项目 Scope

- 默认继承 Pi；明确展示当前来源是“继承 Pi”还是“项目自定义”。Pi 未配置 Scope 时遵循其默认行为，全部可用模型参与继承列表；这与自定义空列表不同。
- 自定义内容完全覆盖，只有显式恢复继承后才重新跟随 Pi 默认 Scope。
- 模型身份区分供应商和模型 ID；保持确定的列表顺序。
- 保留继承列表中的模型思考等级覆盖，避免编辑成员时无意丢失现有等级语义。
- 保存的模型暂时不可用时，不静默删除项目设置；不可用成员不参加选择或轮切。
- 项目删除时清理其 Scope 设置。

### R3. 草稿式批量编辑

仅桌面应用和桌面布局的 WebUI 提供以下管理操作：

- 从当前有效列表初始化勾选状态；继承了五个模型时，打开编辑仍勾选五个。
- 支持搜索、多选、全选当前搜索结果、清空选择。
- 编辑期间取消勾选不立即隐藏该模型，方便继续操作。
- 草稿不改变正式列表、实际 Scope 或快捷键行为。
- “应用到项目”一次性保存完整草稿；取消或关闭放弃未提交修改。
- 未改变继承列表时，不创建自定义覆盖。
- “恢复继承 Pi”与“清空选择”明确区分。
- 保存中防止重复提交；保存失败保留草稿，正式设置保持原样。

### R4. 行为一致性

- Pilo 的 Scope 视图和 Scope 轮切使用同一份有效列表，不由 Pi 原生轮切另行选择模型。
- 全部模型轮切保持现有行为，不被项目 Scope 限制。
- 自定义空 Scope 或没有可用成员时，Scope 轮切无操作，不回退到全部模型。
- 一模型 Scope 的重复轮切不产生无意义的模型切换。
- Scope 编辑不终止、重启或改变正在运行的对话，不自动选择新模型。
- 同一 Host 上桌面端和 WebUI 共享保存结果；同时编辑时以最后成功保存为准，不覆盖尚未提交的本地草稿。

### R5. 平台与交互

- 支持 Local/WSL/SSH 项目，以及草稿、历史会话和临时会话的模型选择器。
- 移动端保留模型搜索、全部/Scope 切换、模型选择、来源展示与设置同步；不显示编辑、批量操作或恢复继承入口。考虑触控目标、安全区和搜索软键盘遮挡。
- 桌面保留原有“模型 / 推理等级”两级菜单与紧凑列表，搜索和 Scope 仅扩展模型选择，不改成移动端平铺样式。
- 桌面端支持键盘搜索、导航和操作，提供可访问名称及状态。
- 模型与推理等级弹窗在输入区上方展开，保留适当间距，不贴窗口底部，也不过度上移；面板控件沿用整体风格。
- 新增内置文案同时支持 zh-CN 与 en-US。

## Acceptance Criteria

- [ ] 未设置项目 Scope 时，Scope 视图与 Pi 默认解析结果一致；默认 Scope 更新后按现有模型目录刷新机制反映变化。
- [ ] 搜索模型名称、ID 或供应商可在全部和 Scope 视图中找到匹配结果，且不改变模型。
- [ ] 打开编辑时完整保留当前勾选；连续修改多个模型不会逐项应用。
- [ ] 应用后只使用完整的项目列表；Pi 全局包含的其他模型不会被合并回来。
- [ ] 取消、关闭或未修改时退出，不创建或修改项目覆盖。
- [ ] 保存失败时原 Scope 仍生效，草稿可继续编辑或重试。
- [ ] 清空并应用后 Scope 为空；轮切不会退回全部模型；恢复继承后重新使用 Pi 默认。
- [ ] 选择器和 Scope 快捷键一致；全部模型快捷键保持原有全部轮切行为。
- [ ] 编辑 Scope 不重启 Pi、不修改当前模型、不丢失临时会话、不干扰流式响应。
- [ ] 重启 Pilo、切换会话或重开 WebUI 后项目 Scope 仍然存在；不同项目互不影响。
- [ ] 桌面应用和桌面布局的 WebUI 能编辑同一 Host 上的设置；移动端能同步读取和使用保存结果，且不显示管理入口。
- [ ] 全流程不写 Pi settings.json 或其他 Pi 配置，不要求 Pi 上游 API 变更，不启动 WebUI 自己的模型探测会话。
- [ ] 桌面保留模型与推理等级的两级菜单，模型子面板可搜索和使用 Scope，移动抽屉样式不影响桌面。
- [ ] 移动端软键盘出现时搜索和模型选择仍可用；桌面编辑可用，中英文、键盘和触控交互完整。

## Out of Scope

- 移动窄屏的 Scope 编辑、批量管理和恢复继承；仅使用手机的用户需到桌面布局管理设置。
- 修改 Pi 全局或项目配置、调用 Pi 内置 /scope-models 来保存设置。
- 修改独立 Pi 的内部 Scope、增加 Pi RPC 命令、使用私有 SDK 字段或重启 Pi 来应用 Scope。
- 合并模式、排除列表、模型排序拖拽、模型别名或新的模型供应商配置。
- 实时监视 Pi settings.json；默认值更新复用现有 Pi 模型目录缓存和刷新机制。
- 自动创建或运行测试、构建；验证命令需用户明确授权后执行。
